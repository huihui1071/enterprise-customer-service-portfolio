# 权限矩阵与错误码

## 1. 权限矩阵

| 操作 | 医生 | 助理 | 客服 | 管理员 |
|---|---|---|---|---|
| 查询本人负责病例 | 允许 | 仅获授权医生病例 | 仅工单处理所需且需审计 | 仅授权运维场景 |
| 查询同机构其他医生病例 | 默认拒绝 | 默认拒绝 | 默认拒绝 | 默认拒绝 |
| 查询跨机构病例 | 拒绝 | 拒绝 | 拒绝 | 拒绝 |
| 创建本人机构工单 | 允许 | 允许 | 允许 | 允许 |
| 查询本人提交工单 | 允许 | 允许 | 允许 | 允许 |
| 处理工单 | 拒绝 | 拒绝 | 已分派或所在团队 | 允许 |
| 修改病例状态 | MVP 不开放 | 拒绝 | 拒绝 | MVP 不开放 |
| 管理任职与授权 | 拒绝 | 拒绝 | 拒绝 | 允许并审计 |

所有“允许”还要求 User、Organization、Membership 当前有效。对象级权限不能只用角色判断。

## 2. 公共错误结构

```json
{
  "error": {
    "code": "CASE_ACCESS_DENIED",
    "message": "无法访问该病例，请检查病例编号或联系管理员。",
    "retryable": false
  },
  "trace_id": "trace-example"
}
```

## 3. 错误码

| HTTP | 内部错误码 | 是否重试 | 对外策略 |
|---:|---|---|---|
| 400 | `INVALID_REQUEST` | 否 | 提示检查输入格式 |
| 401 | `AUTH_REQUIRED` | 否 | 提示重新登录 |
| 401 | `TOKEN_EXPIRED` | 否 | 刷新或重新获取 Token |
| 403 | `ACCOUNT_FROZEN` | 否 | 提示账号不可用 |
| 403 | `MEMBERSHIP_INACTIVE` | 否 | 病例场景使用统一安全提示 |
| 403 | `CASE_ACCESS_DENIED` | 否 | 与病例不存在使用相同提示 |
| 404 | `CASE_NOT_FOUND` | 否 | 与病例无权限使用相同提示 |
| 404 | `TICKET_NOT_FOUND` | 否 | 不泄露其他用户工单详情 |
| 409 | `IDEMPOTENCY_CONFLICT` | 否 | 同一键请求体不一致，拒绝处理 |
| 429 | `RATE_LIMITED` | 是 | 按 `Retry-After` 延迟重试 |
| 500 | `INTERNAL_ERROR` | 是 | 用户侧降级，记录 trace_id |
| 503 | `DEPENDENCY_UNAVAILABLE` | 是 | 降级并建议稍后重试或转人工 |
| 504 | `DEPENDENCY_TIMEOUT` | 是 | 不重复输出，不盲目重复建单 |

病例的 403 与 404 在 HTTP 状态上可以区分供客户端处理，但响应正文不得泄露对象是否存在；安全测试同时验证正文与日志。
