# 病例权限测试矩阵

## 1. 目的

本矩阵同时指导 Mock 数据生成、后端鉴权实现和自动化测试。测试数据均为模拟数据。

## 2. 决策顺序

病例查询按以下顺序校验：

```text
可信 Token 身份
→ User.account_status
→ Organization.status
→ Membership 角色、状态和有效期
→ Case.organization_id
→ 医生病例归属或助理授权关系
→ 返回最小必要数据
```

请求正文中的 `user_id`、`doctor_id` 和 `organization_id` 只可作为业务参数，不可覆盖 Token 中的可信身份。

## 3. 核心测试矩阵

| 编号 | 场景 | 关键数据条件 | 预期结果 | 内部原因码 |
|---|---|---|---|---|
| AUTH-001 | 在职医生查询自己负责的病例 | 用户 active；doctor Membership 有效；`primary_doctor_user_id` 匹配 | 允许 | `ACCESS_GRANTED` |
| AUTH-002 | 在职医生查询同机构其他医生病例 | Membership 有效，但 `primary_doctor_user_id` 不匹配 | 拒绝 | `CASE_ACCESS_DENIED` |
| AUTH-003 | 助理查询已授权医生病例 | assistant Membership、Assignment 均有效；病例与三者同机构 | 允许 | `ACCESS_GRANTED` |
| AUTH-004 | 助理查询未授权医生病例 | assistant Membership 有效，但无有效 Assignment | 拒绝 | `ASSIGNMENT_REQUIRED` |
| AUTH-005 | 离职医生查询原机构病例 | `Membership.status = inactive` 或有效期已结束 | 拒绝 | `MEMBERSHIP_INACTIVE` |
| AUTH-006 | 冻结用户查询自己病例 | `User.account_status = frozen` | 拒绝 | `ACCOUNT_FROZEN` |
| AUTH-007 | 在职医生查询其他机构病例 | 在目标机构无有效 Membership，病例也不属于当前机构 | 拒绝 | `CROSS_ORG_ACCESS_DENIED` |
| AUTH-008 | 查询不存在的病例号 | `case_id` 不存在 | 拒绝 | `CASE_NOT_FOUND` |

## 4. 对外响应策略

AUTH-002、AUTH-004、AUTH-005、AUTH-007 和 AUTH-008 对终端用户使用相同的模糊提示，避免泄露病例是否存在：

```text
无法访问该病例，请检查病例编号或联系管理员。
```

后端通过结构化日志保留真实内部原因码、`trace_id`、用户、机构和查询对象，供排障与安全审计使用。冻结账号可返回账号不可用提示，但不得继续泄露病例信息。

## 5. 最小 Mock 账号组合

| Mock 身份 | 用途 |
|---|---|
| 在职医生 A | AUTH-001、AUTH-002、AUTH-007 |
| 同机构在职医生 B | 为 AUTH-002 提供其他医生病例 |
| 已授权助理 A | AUTH-003 |
| 未授权助理 B | AUTH-004 |
| 离职医生 C | AUTH-005 |
| 冻结医生 D | AUTH-006 |
| 其他机构医生 E | AUTH-007 |

病例数据至少覆盖医生 A、医生 B 和其他机构医生 E，并额外准备一个永远不存在的病例号用于 AUTH-008。
