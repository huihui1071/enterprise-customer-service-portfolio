# 会话记忆与指代消解契约

## 1. 边界

- Dify Conversation Variables 保存会话内任务状态和业务对象引用。
- Backend 保存病例、工单、权限和审计事实；每次工具调用都重新鉴权。
- 聊天历史只帮助识别意图和指代表达，不可直接提供可信病例号。
- 第一版不跨会话恢复病例，不根据患者姓名推测病例。

## 2. Conversation Variables

| 变量 | 类型 | 默认值 | 写入时机 | 清理时机 | 可直接作为 API 参数 |
|---|---|---:|---|---|---|
| `active_intent` | string | `""` | 识别出当前任务 | 任务完成或放弃 | 否 |
| `task_status` | string | `idle` | 每次状态转移 | 新会话 | 否 |
| `pending_action` | string | `""` | 等待补参或确认 | 参数补齐、任务切换 | 否 |
| `pending_slot` | string | `""` | 缺少必要参数 | 参数补齐、任务切换 | 否 |
| `clarify_count` | integer | `0` | 每次有效澄清加一 | 完成、放弃、新任务 | 否 |
| `case_id_candidate` | string | `""` | 本轮提取到病例号 | 鉴权后提升或失败清理 | 否 |
| `active_case_id` | string | `""` | 本任务病例鉴权成功 | 任务完成、失败或换病例 | 是，但调用前仍须鉴权 |
| `recent_confirmed_case_id` | string | `""` | 病例鉴权成功 | 过期、权限失败、新会话 | 是，但调用前仍须鉴权 |
| `recent_case_ids` | string(JSON array) | `[]` | 病例鉴权成功后去重追加 | 新会话；最多保留 3 个 | 仅用于候选确认 |
| `case_reference_status` | string | `none` | 候选解析后 | 任务完成或清理 | 否 |
| `last_case_confirmed_turn` | integer | `0` | 病例鉴权成功 | 新会话 | 否 |
| `active_ticket_id` | string | `""` | 工单创建或查询成功 | 任务结束或权限失败 | 是，但调用前仍须鉴权 |
| `last_topic` | string | `""` | 知识问答完成 | 新会话 | 否 |
| `problem_summary` | string | `""` | 高风险信息收集 | 建单成功或放弃 | 否 |
| `turn_index` | integer | `0` | 每个用户轮次加一 | 新会话 | 否 |

## 3. 状态与优先级

`task_status` 只允许：`idle`、`collecting_slots`、`waiting_confirmation`、`ready_to_execute`、`executing`、`completed`、`failed`、`handoff`。

处理优先级固定为：

```text
高风险硬规则
> 待办任务续接
> 本轮显式病例/工单
> 唯一指代恢复
> 普通知识意图
> 兜底澄清
```

## 4. 指代规则

- “刚才那个病例”等回指，在最近 10 个用户轮次内只有一个已鉴权病例时，可恢复该病例并重新鉴权。
- 最近存在多个病例时，设置 `case_reference_status=ambiguous` 并要求用户从候选中确认。
- “另一个病例”清空当前病例和候选，进入 `collecting_slots`。
- 新会话、记忆过期、历史鉴权失败时不得恢复。
- 查询成功后保留最近病例引用，但清空当前任务的临时字段。
- 权限失败时从最近病例列表移除对应病例，避免后续再次自动引用。

## 5. 澄清规则

- 每轮最多只问一个关键问题。
- 缺少病例号时 `clarify_count += 1`，最多澄清 2 次。
- 两次后仍未补齐，结束自动追问并提供重新描述或转人工选项。
- 澄清期间出现高风险词时立即抢占并进入人工链路。

## 6. 成功写入

病例 API 鉴权成功后：

```text
active_case_id = resolved_case_id
recent_confirmed_case_id = resolved_case_id
recent_case_ids = append_unique(resolved_case_id, max=3)
last_case_confirmed_turn = turn_index
case_reference_status = confirmed
pending_action = ""
pending_slot = ""
clarify_count = 0
```

回复必须回显最终使用的病例号，使用户能够发现错误指代。
