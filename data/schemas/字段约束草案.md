# 字段约束草案

## 1. 约束说明

| 约束 | 作用 |
|---|---|
| `PRIMARY KEY` | 唯一标识一行，同时隐含唯一且不能为空 |
| `FOREIGN KEY` | 保证引用的关联对象真实存在 |
| `NOT NULL` | 字段必须有值 |
| `UNIQUE` | 防止业务标识或幂等键重复 |
| `CHECK` | 将角色、状态等字段限制在合法枚举范围内 |

## 2. User

| 字段 | 约束 |
|---|---|
| `user_id` | `PRIMARY KEY` |
| `display_name` | `NOT NULL` |
| `account_status` | `NOT NULL`，`CHECK (active, frozen, disabled)` |
| `created_at` | `NOT NULL` |
| `updated_at` | `NOT NULL` |

## 3. Organization

| 字段 | 约束 |
|---|---|
| `organization_id` | `PRIMARY KEY` |
| `organization_code` | `UNIQUE + NOT NULL` |
| `organization_name` | `NOT NULL` |
| `status` | `NOT NULL`，`CHECK (active, suspended, closed)` |
| `created_at` | `NOT NULL` |
| `updated_at` | `NOT NULL` |

## 4. Membership

| 字段 | 约束 |
|---|---|
| `membership_id` | `PRIMARY KEY` |
| `user_id` | `FOREIGN KEY -> User.user_id + NOT NULL` |
| `organization_id` | `FOREIGN KEY -> Organization.organization_id + NOT NULL` |
| `role` | `NOT NULL`，`CHECK (doctor, assistant, support, admin)` |
| `status` | `NOT NULL`，`CHECK (active, inactive)` |
| `valid_from` | `NOT NULL` |
| `valid_to` | 允许为空 |
| `created_at` | `NOT NULL` |
| `updated_at` | `NOT NULL` |

业务约束：同一用户在同一机构、同一角色下不能同时存在两条有效 Membership。为了保留再次入职的历史，不对 `(user_id, organization_id, role)` 直接设置永久唯一，而由应用逻辑或数据库条件唯一索引限制有效记录。

## 5. AssistantDoctorAssignment

| 字段 | 约束 |
|---|---|
| `assignment_id` | `PRIMARY KEY` |
| `organization_id` | `FOREIGN KEY -> Organization.organization_id + NOT NULL` |
| `assistant_user_id` | `FOREIGN KEY -> User.user_id + NOT NULL` |
| `doctor_user_id` | `FOREIGN KEY -> User.user_id + NOT NULL` |
| `status` | `NOT NULL`，`CHECK (active, revoked, expired)` |
| `valid_from` | `NOT NULL` |
| `valid_to` | 允许为空 |
| `created_at` | `NOT NULL` |
| `updated_at` | `NOT NULL` |

业务约束：助理和医生必须在 `organization_id` 对应机构中分别具有有效的 `assistant` 和 `doctor` Membership；不能只依赖外键证明任职或角色正确。

## 6. Case

| 字段 | 约束 |
|---|---|
| `case_id` | `PRIMARY KEY` |
| `organization_id` | `FOREIGN KEY -> Organization.organization_id + NOT NULL` |
| `primary_doctor_user_id` | `FOREIGN KEY -> User.user_id + NOT NULL` |
| `subject_ref` | `NOT NULL` |
| `status` | `NOT NULL`，合法值由病例状态机约束 |
| `created_at` | `NOT NULL` |
| `updated_at` | `NOT NULL` |

业务约束：主治医生必须在病例所属机构具有有效的医生 Membership。医生离职后保留历史关系，通过重新分配操作变更当前主治医生并留下审计记录。

## 7. Ticket

| 字段 | 约束 |
|---|---|
| `ticket_id` | `PRIMARY KEY` |
| `ticket_type` | `NOT NULL`，合法值由工单类型字典约束 |
| `priority` | `NOT NULL`，`CHECK (P0, P1, P2)` |
| `status` | `NOT NULL`，合法值由工单状态机约束 |
| `organization_id` | `FOREIGN KEY -> Organization.organization_id + NOT NULL` |
| `reporter_user_id` | `FOREIGN KEY -> User.user_id + NOT NULL` |
| `case_id` | `FOREIGN KEY -> Case.case_id`，允许为空且不唯一 |
| `assignee_user_id` | `FOREIGN KEY -> User.user_id`，允许为空 |
| `summary` | `NOT NULL` |
| `description` | `NOT NULL` |
| `evidence` | 允许为空 |
| `risk_level` | `NOT NULL` |
| `source` | `NOT NULL` |
| `idempotency_key` | `UNIQUE + NOT NULL` |
| `created_at` | `NOT NULL` |
| `updated_at` | `NOT NULL` |
| `resolved_at` | 允许为空 |

一个病例可以关联多个工单，因此 `Ticket.case_id` 不能设置 `UNIQUE`。不涉及病例的咨询类工单可以不填写 `case_id`。

## 8. TicketEvent

| 字段 | 约束 |
|---|---|
| `event_id` | `PRIMARY KEY` |
| `ticket_id` | `FOREIGN KEY -> Ticket.ticket_id + NOT NULL` |
| `event_type` | `NOT NULL` |
| `operator_user_id` | `FOREIGN KEY -> User.user_id + NOT NULL` |
| `from_status` | 允许为空 |
| `to_status` | 允许为空 |
| `event_detail` | 允许为空 |
| `created_at` | `NOT NULL` |

## 9. 删除与历史保留策略

- User、Organization、Membership、Case、Ticket 和 TicketEvent 不进行物理删除，使用状态字段失效或关闭。
- 外键默认采用限制删除策略，避免删除被业务数据引用的用户或机构。
- 离职、冻结、授权撤销和状态变化保留历史记录。
- Mock 数据需要覆盖正常、冻结、离职、跨机构、授权过期和重复请求等边界情况。
