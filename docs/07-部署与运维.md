# 部署与运维

## 当前交付形态

- Dify Cloud：承载对话编排、意图路由、知识检索和工具调用。
- FastAPI：承载身份校验、病例查询、工单创建及审计。
- SQLite：本地演示数据；生产迁移目标为 PostgreSQL。
- Docker Compose：提供可复现的本地部署入口。

## 环境分层

| 环境 | 数据 | 用途 | 发布要求 |
|---|---|---|---|
| Local | 固定 Mock Seed | 开发、接口和权限测试 | 自动测试通过 |
| Staging | 独立 Mock 数据 | Dify 端到端回归 | Eval 达标且无 P0 缺陷 |
| Demo | 脱敏 Mock 数据 | 面试展示 | 固定账号、可一键恢复 |

## 发布流程

1. 运行数据校验、Backend 测试和 Backend Eval。
2. 构建容器并检查 `/health`。
3. 部署公网 HTTPS Backend，配置 JWT 密钥与允许来源。
4. 在 Dify 草稿中更新 URL、请求头和错误分支。
5. 跑病例查询、高风险建单、幂等和越权回归。
6. 保存 Dify DSL 版本，人工确认后发布。

## 可观测性

- 每次请求返回 `trace_id` 和耗时 Header。
- 审计日志记录调用人、对象、授权结果和内部拒绝原因。
- 外部错误提示不暴露病例是否存在，内部日志保留真实原因。
- 重点监控 API 成功率、P95 延迟、鉴权拒绝、重复工单和高风险分派。

## 故障与回滚

- API 超时：Dify 返回降级文案，不把猜测当作病例状态。
- Backend 不可用：停止确定性查询与建单，保留人工入口。
- 新 DSL 回归失败：继续使用上一个已导出的 DSL，不发布草稿。
- 数据异常：重新生成固定 Seed 并重跑校验。
