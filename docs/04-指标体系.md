# 指标体系

## 1. 指标状态约定

| 标签 | 含义 |
|---|---|
| baseline_assumption | 为作品集设定的模拟现状，不是真实公司数据 |
| target | 设计目标，尚未证明达成 |
| measured | 通过固定数据集和脚本得到、可以复现的结果 |

任何对外材料必须保留状态。只有 `measured` 可以写成“达到”。

截至 2026-08-23，首轮 Dify API Eval 共提交 150 条：139 条成功执行，其中 126 条通过行为断言，通过率 90.65%；P50 4.52 秒，P95 8.21 秒。11 条因 DeepSeek 余额不足产生执行错误，不进入行为准确率分母。该结果是首轮发布版本的 `measured` 基线，不代表最新草稿或最终达标结果。

## 2. 指标树

```text
北极星：有效问题解决率
├── 业务价值
│   ├── 自动解决率
│   ├── 人工节省时长
│   └── 首次响应时间
├── AI 质量
│   ├── 路由准确率
│   ├── 知识 Recall@K
│   ├── 回答正确率
│   └── 引用正确率
├── 工具质量
│   ├── 工具选择准确率
│   ├── 参数正确率
│   ├── API 成功率
│   └── 重复建单率
├── 安全护栏
│   ├── 高风险识别召回率
│   ├── 应转未转率
│   ├── 越权访问成功数
│   └── 敏感信息泄露数
└── 工程健康
    ├── P50/P95 延迟
    ├── 错误率
    ├── 单会话成本
    └── 可追踪率
```

## 3. 核心指标口径

### 3.1 有效问题解决率

```text
有效问题解决率 = 已正确解决的问题会话数 / 有效问题会话总数
```

正确解决包括：AI 完成低风险问题，或高风险问题正确转人工并完成必要交接。无输入、测试噪声、刷屏和无法识别内容不进入分母。

### 3.2 自动解决率

```text
自动解决率 = AI 独立正确闭环的有效会话数 / 适合自动化的有效会话数
```

高风险正确转人工不进入“适合自动化”分母，避免用自动化率惩罚安全决策。沉默离开不能直接判断为解决。

### 3.3 路由准确率

```text
路由准确率 = 主路由与人工标签一致的样本数 / 路由样本总数
```

同时报告各类别 Precision、Recall 和混淆矩阵。高风险类别以 Recall 为优先。

### 3.4 知识 Recall@K

```text
Recall@K = Top K 召回中包含标准证据的样本数 / 有标准证据的样本总数
```

需固定知识库版本、切片版本、embedding 和 rerank 配置。

### 3.5 回答正确率

由规则检查、LLM Judge 与人工抽检组合判定，至少覆盖：事实正确、证据一致、完整、遵循边界和可执行。

### 3.6 引用正确率

```text
引用正确率 = 引用真实存在且支持对应断言的引用数 / 总引用数
```

模型生成一个看似合理的文档名不算正确引用。

### 3.7 高风险识别召回率

```text
高风险识别召回率 = 被正确拦截的高风险样本 / 全部高风险样本
```

同时监控误报率，避免所有问题都转人工。

### 3.8 API 成功率

```text
API 成功率 = 产生符合业务预期响应的调用数 / 有效调用总数
```

网络成功但返回错误数据不算成功。

### 3.9 重复建单率

```text
重复建单率 = 因同一幂等请求生成的额外工单数 / 建单请求总数
```

目标为 0。

## 4. 目标值

| 指标 | target | 说明 |
|---|---:|---|
| 路由准确率 | >= 92% | 需同时报告分类指标 |
| 知识问答正确率 | >= 88% | 仅在有有效证据样本上计算 |
| 引用正确率 | >= 95% | 引用必须支持具体断言 |
| 高风险识别召回率 | >= 98% | 安全护栏 |
| 应转未转率 | <= 1% | 高风险样本 |
| 病例越权访问成功数 | 0 | 硬门槛 |
| 敏感信息泄露数 | 0 | 硬门槛 |
| 自动解决率 | >= 65% | 只统计适合自动化场景 |
| API 成功率 | >= 99% | 排除主动注入的故障测试 |
| 重复创建工单数 | 0 | 幂等硬门槛 |
| P95 首次响应 | <= 8 秒 | 知识问答链路 |
| 关键调用可追踪率 | 100% | trace_id 可贯穿链路 |

## 5. 发布门槛

以下任一条件不满足，不进入下一阶段灰度：

- 高风险召回率低于目标。
- 出现任何病例越权访问或敏感信息泄露。
- P0 主链路存在错误并行输出。
- 病例状态可能由模型或知识库编造。
- 工单重试会产生重复工单。
- 评测结果不能由固定版本数据和脚本复现。

## 6. 当前实测状态

Backend 已生成首份可复现 `measured` 报告：`evals/reports/backend-eval-latest.json`。

| 指标 | measured | 范围 |
|---|---:|---|
| 权限决策准确率 | 100%（8/8） | 固定病例权限边界集 |
| 病例越权访问成功数 | 0 | 6 条拒绝场景 |
| 幂等建单 | 通过 | 同一键两次请求只生成一个工单 |
| 高风险立即分派 | 通过 | P0 且分派 `high-risk-support` |

以上只证明确定性 Mock Backend。AI 路由、RAG、引用、高风险召回、端到端成功率和延迟仍未形成正式 `measured` 指标。

初始浏览器探索 bad case：

- 普通知识问题错误并行输出病例号澄清。
- 明确包含病例号的状态查询未进入病例 API 链路。
- 高风险问题可以在 Mock 服务创建工单，但尚未验证幂等、权限和故障降级。

Dify 草稿已修复前两项路由问题并完成单条浏览器回归，但草稿尚未发布，新 Backend 也尚未公网接入，因此不将单条回归转换为准确率指标。

这些结果用于阶段 4 重构输入，不代表完整评测结论。
