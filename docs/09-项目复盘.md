# 项目复盘

## 已完成

- 从六类场景中定义用户、价值、优先级和 AI 自动化边界。
- 建立组织、任职、助理授权、病例、工单和事件模型。
- 生成可复现的 Mock 数据、知识数据和 150 条 Eval。
- 实现带 JWT、对象级鉴权、幂等、审计和故障注入的 FastAPI Backend。
- 修复 Dify 草稿中的错误并行路由与变量类型问题。
- 建立测试、部署手册、指标文档和双岗位讲解材料。

## 做得好的地方

- 将“业务优先级”和“AI 自动化程度”拆开，避免把 P0 等同于全自动。
- 用确定性 API 处理病例事实，用人工处理高风险判断，边界清楚。
- 严格区分模拟基线、目标指标和可复现实测结果。
- 权限设计覆盖角色、组织关系、授权关系和对象归属，不停留在 Demo 级 RBAC。

## 当前缺口

- Backend 已部署为公网 HTTPS 服务，Dify 云端草稿已接入；Render 免费实例闲置后可能冷启动。
- Dify 核心冒烟用例 4/4 通过，但 AI 路由准确率、RAG 正确率、高风险召回率和完整端到端准确率仍需用 150 条测试集评测。
- Docker 配置已提供，但当前机器缺少 Docker，镜像构建尚未验证。
- Dify 修复仍是草稿，未在用户确认后发布。

## 下一阶段

1. 补齐 Dify 的接口错误分支与超时降级。
2. 跑 150 条端到端 Eval，输出错误切片和修复前后对比。
3. 固化 Demo 账号与演示数据，录制一次完整演示。
4. 根据 Eval 结果优化路由、Prompt 和知识 metadata，而不是继续堆叠节点。

## 面试表达

本项目证明的不是“会搭一个聊天机器人”，而是能从业务判断出发，把高频确定性任务和高风险任务放到不同处理路径，并用数据契约、权限、测试、部署和指标把方案落实为可验证原型。
