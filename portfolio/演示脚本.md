# 演示脚本

## 目标

用 6 到 8 分钟展示产品判断和工程交付，不把时间花在逐个展示节点。

## 顺序

1. 用一页场景优先级说明病例查询与临床异常的不同自动化边界。
2. 展示 Dify 普通知识问题，确认只有一个产品答案。
3. 输入不带病例号的状态查询，展示一次澄清。
4. 输入有权限病例，展示 API 返回的确定性状态和下一步。
5. 切换到无权限账号查询同一病例，展示统一安全提示。
6. 输入高风险异常，展示不诊断、收集证据、创建 P0 工单和人工分派。
7. 重放同一建单请求，展示返回同一工单号。
8. 打开 Eval 报告，说明哪些是 measured、哪些仍是 target。

## 测试身份

| 身份 | 用途 |
|---|---|
| `USR-DOC-001` | 查询本人病例 `CASE-2026-0025` |
| `USR-DOC-001` | 越权查询同机构病例 `CASE-2026-0019` |
| `USR-AST-001` | 查询已授权医生病例 |
| `USR-DOC-025` | 展示离职 Membership 失效 |
| `USR-DOC-028` | 展示冻结账号阻断 |

## 结束语

这个项目最重要的不是 Dify 节点数量，而是从业务优先级到数据契约、鉴权、幂等、测试、Eval 和发布门槛形成了闭环，并且所有结论都能回到代码或报告。
